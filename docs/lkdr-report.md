# Отчет по покупкам LKDR

Скрипт `scripts/reports/lkdr_report.py` строит текстовый отчет по покупкам из SQLite-базы `lkdr.db`.
Это основной отчёт из набора Python-отчётов; все они доступны через меню `make report`
(см. [Разработку](development.md#python-отчёты-меню-и-свои-скрипты)).
Он использует данные чеков ФНС из таблиц `fiscal_data`, `fiscal_data_items`, `receipts` и `brands`.

## Требования

- Python 3.10 или новее.
- Файл базы данных `lkdr.db`.
- Внешние Python-пакеты не нужны: используется только стандартная библиотека.
- Для AI-выводов нужен установленный и авторизованный AI CLI (по умолчанию Codex; агент настраивается секцией `ai` в `config.json` — см. [Конфигурацию](configuration.md#ai)).

## Быстрый запуск

Из корня проекта:

```bash
make lkdr-report
```

Или напрямую:

```bash
./scripts/reports/lkdr_report.py --db lkdr.db
```

По умолчанию отчет строится за последние 30 дней относительно самого свежего чека в базе
и сравнивает их с предыдущими 30 днями.

## Запуск через Makefile

Частые сценарии вынесены в `Makefile`:

```bash
make lkdr-report
make lkdr-report-short
make lkdr-report-file
```

- `make lkdr-report` — отчет за 30 дней с топ-10 строками.
- `make lkdr-report-short` — короткий отчет с топ-5 строками.
- `make lkdr-report-file` — сохранить отчет в `lkdr-report.txt`.

Параметры можно переопределять переменными:

```bash
make lkdr-report LKDR_DAYS=7 LKDR_TOP=20
make lkdr-report LKDR_DB=/path/to/lkdr.db
make lkdr-report LKDR_COLOR=always
make lkdr-report LKDR_AI_ARGS=--ai-summary
make lkdr-report-file LKDR_REPORT_OUT=reports/lkdr-july.txt
```

Отчет за 90 дней:

```bash
make lkdr-report LKDR_DAYS=90
```

## Параметры

```bash
./scripts/reports/lkdr_report.py --db lkdr.db --days 30 --top 10
```

- `--db` — путь к SQLite-базе. По умолчанию `lkdr.db`.
- `--days` — количество дней в отчете. По умолчанию `30`.
  Для сравнения используется предыдущий период такой же длины: при `--days 30` сравниваются последние 30 дней и период 30-60 дней назад.
- `--top` — сколько строк показывать в топах магазинов и товаров. По умолчанию `10`.
- `--basket-days` — окно расчёта корзины продуктов на неделю, дней (по умолчанию `180`; `0` отключает секцию корзины).
- `--color` — режим цветного вывода: `auto`, `always` или `never`. По умолчанию `auto`.
- `--format` — `text` (по умолчанию, рамки для терминала) или `md` — markdown: заголовки `##`/`###` и GFM-таблицы без цвета, адаптировано для вывода в чат AI-агента. Через make: `make lkdr-report LKDR_FORMAT=md`.
- `--as-of` — дата и время конца отчетного периода в ISO-формате. Если не указано, используется дата самого свежего чека.
- `--currency-store` — принудительно указать валюту для точного названия магазина.
- `--currency-receipt` — принудительно указать валюту для конкретного `receipt_key`.
- `--ai-summary` — добавить AI-выводы и рекомендации через AI CLI.
- `--ai-command` — команда AI CLI с аргументами (промпт подаётся на stdin). По умолчанию — `ai.command` из `config.json`, иначе `codex exec --color never --sandbox read-only -`.
- `--ai-timeout` — сколько секунд ждать AI-ответ. По умолчанию `180`.
- `--config` — путь к `config.json` с настройками отчётов (`ai.command`). По умолчанию `config.json` в текущем каталоге.

Пример с фиксированной датой окончания периода:

```bash
./scripts/reports/lkdr_report.py --db lkdr.db --days 30 --as-of '2026-07-05 16:35:00+03:00'
```

## Параметры HTML-отчёта (ai_report.py)

HTML-отчёт «Месяц в чеках» (`make ai-report`) имеет свой набор аргументов
(полный список — `ai_report.py --help`):

- `--db`, `--days`, `--top`, `--as-of`, `--basket-days` — те же по смыслу,
  что у текстового отчёта (`--days` задаёт длину периода сравнения).
- `--out-dir` — каталог для `lkdr-YYYY-MM.html` (по умолчанию `reports`).
- `--currency` — `RUB`/`KZT` или `auto` (по умолчанию): основная валюта
  периода, HTML-отчёт строится по одной валюте.
- `--template` — путь к шаблону (по умолчанию `scripts/templates/lkdr-report.html`).
- `--no-ai` — не вызывать AI CLI: карточки и план закупки собираются
  детерминированно из данных.
- `--ai-command`, `--ai-timeout`, `--config` — как у текстового отчёта.

Через make аргументы передаются переменной `AI_REPORT_ARGS`:
`make ai-report AI_REPORT_ARGS="--as-of 2026-09-30"`. Расчёты переиспользуют
`lkdr_report.py`, поэтому методика сумм одинаковая.

## Валюты

В текущей схеме `lkdr.db` нет отдельного поля валюты. Скрипт по умолчанию считает чеки рублевыми.
Если в текстовых полях чека есть явные признаки Казахстана (`Казахстан`, `Алматы`, `.kz` и т.п.), чек будет отнесен к `KZT`.

Для неявных случаев валюту можно задать вручную:

```bash
./scripts/reports/lkdr_report.py --db lkdr.db --days 90 --currency-store 'Kaspi.kz=KZT'
./scripts/reports/lkdr_report.py --db lkdr.db --days 90 --currency-receipt 'receipt_key=KZT'
```

Через `make` дополнительные аргументы передаются переменной `LKDR_CURRENCY_ARGS`:

```bash
make lkdr-report LKDR_DAYS=90 LKDR_CURRENCY_ARGS="--currency-store 'Kaspi.kz=KZT'"
```

Отчет не складывает разные валюты вместе. Для каждой валюты выводится отдельная секция, например `Currency: RUB` и `Currency: KZT`.

## Что входит в отчет

Скрипт выводит:

- период отчета;
- период сравнения;
- сравнение текущего периода с предыдущим;
- краткое резюме по каждой валюте;
- чистую сумму расходов;
- gross-сумму до возвратов;
- категории расходов с суммой, сравнением и долей;
- количество покупочных чеков;
- средний чек;
- средние расходы в день;
- возвраты и отмены;
- проигнорированные чеки закрытия предоплаты;
- топ магазинов по сумме;
- главные изменения по магазинам и товарам;
- топ товаров по сумме;
- сервисы и комиссии;
- повторяющиеся покупки.

Структура отчета:

- `Короткий вывод` — несколько строк с главным изменением расходов.
- `Сравнение` — сравнение текущего периода с предыдущим периодом такой же длины.
- `Категории` — группировка товаров по бытовым категориям: молочные продукты, мясо и птица, рыба, овощи и фрукты, хлеб и выпечка, бакалея, напитки, сладости и снеки, готовая еда, дом и ремонт, одежда, бытовая химия, аптека, электроника, транспорт, связь и подписки, ЖКХ и услуги, косметика и гигиена, аксессуары, сервисы и прочее.
- `Разбор Прочего` — что именно осталось без категории: топ позиций с долями от суммы Прочего и хвост одной строкой, чтобы «Прочее» не было дырой в бюджете.
- `Корзина продуктов на неделю` — рекомендации закупок по регулярным покупкам за отдельное окно (`--basket-days`, по умолчанию 180 дней = 6 месяцев). Позиция считается регулярной после 3+ чеков за окно. Колонка `Как часто` — фактический интервал между закупками позиции по чекам окна; колонка `Брать` — сколько взять за одну закупку с сезонной поправкой и округлением вверх до целой упаковки (в скобках — примерная стоимость закупки по средней цене из чеков): шаг упаковки выводится из истории разовых покупок (все количества целые — шаг 1 «шт»; иначе НОД разовых количеств, например 0.9/1.8/2.7 → 0.9; плавающий вес — без шага, округление до 0.1), запись вида `2×0.9` означает «две упаковки по 0.9». Группировка таблицы — по типовым срокам годности (скоропортящееся — каждую неделю, длительного хранения — раз в 2-4 недели или запасом); `~Сумма/нед` — средний расход. Количество и сумма скорректированы сезонностью по месяцу конца периода: над таблицей — сводка «Сезонность (месяц)» с множителями групп (мороженое и прохладительные напитки зимой ниже, ягоды и летние фрукты летом выше, горячие напитки зимой выше), в таблице — колонка `Сезон` с множителем позиции (×1.6 — брать чаще, ×0.5 — реже, «—» — сезон не влияет).
- `Главные изменения` — крупнейшие изменения по магазинам и товарам.
- `Итоги` — основные итоговые метрики.
- `Корректировки` — возвраты, отмены и дублирующие чеки предоплаты.
- `Основная разбивка` — топ магазинов.
- `Товары` — топ товаров, сервисы/комиссии и повторяющиеся покупки.

В топах магазинов, товаров и повторяющихся покупок показываются значения текущего и предыдущего периода, а также изменение.
Для расходов рост подсвечивается красным, снижение — зеленым.
В колонке `Доля` показывается мини-бар и процент от всех чистых расходов периода по этой валюте.
Длинные значения в таблицах обрезаются до 75 символов, чтобы отчет оставался читаемым в терминале.
Названия товаров сокращаются до `reports.maxItemNameChars` из `config.json` (по умолчанию 40); в текстовом отчёте по тому же лимиту сокращаются и названия магазинов. Сокращение касается только отображения — суммы считаются по полным названиям. HTML-отчёт ограничение на магазины не применяет: там названия выводятся целиком.
Товары приватных категорий (`reports.privateCategories`, по умолчанию «Аптека и здоровье», «Косметика и гигиена») не выводятся построчно в топах, изменениях, повторяющихся покупках, разборе Прочего и AI-промптах — их суммы видны только на уровне категории.

Блок `Топ повторяющихся покупок` показывает товары, которые остались с положительным net-итогом и встречались больше чем в одном покупочном чеке.
Сервисные строки вроде доставки, упаковки заказа, возвратов и компенсаций из этого блока исключаются.
Сервисные строки выводятся отдельно в блоке `Топ сервисов и комиссий`.

## Цветной вывод

В терминале отчет может использовать цвета:

- синий — заголовки разделов;
- зеленый — снижение расходов или полезное изменение;
- красный — рост расходов;
- желтый — возвраты, отмены и другие корректировки;
- серый — служебная информация и разделители таблиц.

Режим выбирается параметром `--color`:

```bash
./scripts/reports/lkdr_report.py --db lkdr.db --color auto
./scripts/reports/lkdr_report.py --db lkdr.db --color always
./scripts/reports/lkdr_report.py --db lkdr.db --color never
```

Через `make`:

```bash
make lkdr-report LKDR_COLOR=always
```

При сохранении отчета в файл цель `make lkdr-report-file` автоматически отключает цвета.

## AI-выводы

AI-резюме запускается отдельным флагом:

```bash
./scripts/reports/lkdr_report.py --db lkdr.db --days 30 --top 30 --ai-summary
make lkdr-report LKDR_TOP=30 LKDR_AI_ARGS=--ai-summary
```

Скрипт вызывает AI CLI (по умолчанию `codex exec`; агент настраивается секцией `ai` в `config.json` или флагом `--ai-command`, промпт передаётся на stdin) и передает ему агрегированные данные отчета: итоги текущего периода, период сравнения, категории, главные изменения, топ магазинов, топ товаров, сервисы и повторяющиеся покупки.
Сырые чеки целиком в prompt не отправляются.

Prompt учитывает семейный контекст из локального файла `FAMILY.md` (портрет семьи:
состав, привычки питания, акценты; шаблон — `FAMILY.md.dist`, файл в `.gitignore`).
Без файла используется запасная формулировка (2 взрослых и 2 подростка, питаются дома).
AI должен сравнить текущий период с предыдущим, отдельно оценить доли детальных категорий товаров в расходах и выдать краткие выводы, причины изменений, повторяющиеся привычки, что проверить вручную и рекомендации на следующий месяц.

## Интернет-магазины и дубли чеков

Некоторые интернет-магазины, например Ozon, могут присылать два фискальных чека на одну покупку:

- чек предоплаты, где деньги реально списаны;
- чек полного расчета при передаче товара, где сумма закрывается ранее внесенной предоплатой.

В базе такие закрывающие чеки отличаются тем, что `prepaid_sum` равен `total_sum`.
Обычно при этом `cash_total_sum`, `ecash_total_sum`, `credit_sum` и `provision_sum` равны нулю.

Скрипт считает эффективную трату как `total_sum - prepaid_sum`.
Поэтому закрывающие чеки с уже учтенной предоплатой не увеличивают общую сумму, топ магазинов и топ товаров.

## Возвраты и отмены

В фискальных данных возвраты и отмены отличаются полем `operation_type`.
Обычные покупки имеют `operation_type = 1`, а возвраты прихода — `operation_type = 2`.
Также встречаются компенсации с `operation_type = 3`.

Скрипт считает `operation_type = 2` и `operation_type = 3` отрицательными операциями.
Такие чеки уменьшают общую сумму, магазин, день и товары. Если покупка была полностью отменена, товар не попадет в топ.

## Сохранение отчета в файл

Вывод можно перенаправить в текстовый файл:

```bash
./scripts/reports/lkdr_report.py --db lkdr.db > lkdr-report.txt
```
